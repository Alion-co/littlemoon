**وضعیت اجرا (قبلی):** ✅ **۸۷ تست پاس شد** (۲۰ نوامبر): منطق موتور، هشدار الگوها، پیشنهادهای روزانه و کامل بودن ترجمه‌ها تأیید شده. ظاهر و انیمیشن‌ها (۱۲، ۱۵ و تقسیم فایل‌ها) هنوز روی دستگاه اجرا نشدن. آخرین اجرای `flutter run` به‌خاطر نبودن پوشه‌ی `lib/shared/widgets` شکست خورد؛ ۱۶ فایل گمشده‌ی اون پوشه از روی نحوه‌ی استفاده‌شون بازسازی شد (`lib_fixes.zip`، ۲۰ نوامبر) و ایمپورت اضافی `dart:typed_data` در `backup_files.dart` حذف شد. هنوز `flutter analyze` و اجرا روی دستگاه بعد از این بازسازی تأیید نشده.

### نکته‌های نصب (برای همه‌ی آپدیت‌ها)
- چون `generate: true` فعاله، رشته‌های جدید **فقط داخل ARB** ماندگارن. بعد از هر zip: `dart tool/merge_arb.dart` ← `flutter gen-l10n`.
- مسیر ثابت additions: `arb_additions/` در **ریشه‌ی پروژه** (کنار `pubspec.yaml`)، نه داخل `lib/`. اگه `lib/arb_additions` وجود داشته باشه `merge_arb.dart` خطا می‌ده.
- داده‌ی جدید کاربر: notifier رو `implements DataSlice` کن و توی `dataSlicesProvider` (`lib/domain/services/data_registry.dart`) اضافه‌اش کن؛ پشتیبان، بازیابی و ریست خودکار پوشش داده می‌شن.
- **قانون تحویل:** هر آپدیت به‌صورت zip داده می‌شه و ساختار پوشه‌هاش از ریشه‌ی پروژه شروع می‌شه (مثلاً `lib/...`). zip رو ببر توی ریشه‌ی پروژه (کنار `pubspec.yaml`) و با PowerShell باز کن؛ دستور آماده همیشه همراه zip داده می‌شه:
  ```powershell
  Expand-Archive -Path .\نام_زیپ.zip -DestinationPath . -Force
  ```
- zip رو مستقیم داخل ریشه‌ی پروژه باز کن (کنار `pubspec.yaml`)، نه داخل پوشه‌ی جدید.
- قبل از جایگزینی فایل‌ها commit کن.
- فایل قدیمی `lib/core/constants/app_strings.dart` رو دستی پاک کن (جایگزینش `app_info.dart` شده).
- اگه `flutter run` نوشت `Error when reading 'lib/shared/widgets/...'`: پوشه‌ی `lib/shared/widgets` پاک شده. اول `git status` / `git restore lib/shared/widgets` (نسخه‌ی اصلی بهتر از بازسازیه). اگه گیت نداری، `lib_fixes.zip` رو روی ریشه‌ی پروژه باز کن؛ ۱۶ فایل بازسازی‌شده داخلشه (`designed_by.dart` از قبل بود). ظاهر اون فایل‌ها حدسیه (مثلاً آواتارها آیکون‌ان) و اگه نسخه‌ی اصلی رو داری، همون رو بذار.
- اگه نسخه رو بالا بردی، `AppInfo.version` در `app_info.dart` رو هم هم‌خوان کن.

## ۳) مهاجرت Built-in Kotlin (T4): چرا هنوز نه و ترتیب امن

هشدار فعلی **فقط هشداره** و بیلد رو نمی‌شکنه. طبق راهنمای رسمی فلاتر:
- فعال کردن `android.builtInKotlin=true` به **AGP 9+** و **Flutter 3.47+** نیاز داره.
- لاگ تو می‌گه پلاگین `home_widget` هنوز Kotlin Gradle Plugin می‌زنه. تا وقتی مهاجرت نکرده، فعال کردن پرچم بیلد رو می‌شکنه.
- اگه فقط سمت اپ (`android/app/build.gradle.kts`) پاک‌سازی بشه ولی پرچم `false` بمونه، کد Kotlin خودِ برنامه (مثل `MainActivity` و ویجت‌ها) کامپایل نمی‌شه.

**ترتیب:**
1. نسخه‌ی فلاتر: `flutter --version` (باید ≥ ۳٫۴۷ باشه).
2. changelog پکیج `home_widget` در pub.dev رو ببین. اگه نسخه‌ی «Migrates to built-in Kotlin» داره: `flutter pub upgrade home_widget`. اگه نداره، توی مخزنش issue بزن (قالبش توی راهنمای فلاتر هست).
3. بعدش فایل‌های `android/app/build.gradle.kts`، `android/settings.gradle.kts` و `android/gradle.properties` رو بفرست تا تغییرشون بدم: حذف `kotlin-android` و `kotlinOptions`، اضافه کردن `kotlin { compilerOptions { jvmTarget = JVM_17 } }` و `android.builtInKotlin=true`.

### بدهی‌های فنی باقی‌مونده
- فاز ۲ برنامه‌ی سبک‌سازی (۲۱ نوامبر ۲۰۲۶) انجام شد: `cycle_engine` (۷۵۲←۲۵۵)، `insights_cards`/`insights_page`، `HealthPage.build`، `_DailyLogSheetState`، `cycle_hero_card`، `onboarding_page`، `lock_screen`، `charts_page` به فایل‌ها و ویجت‌های کوچک شکسته شدن. هنوز `flutter analyze` و `flutter test` اجرا نشده. `part`‌های `calendar_page`، `about_page` و `widget_gallery` بیرون از فاز ۲ موندن.
- قفل `any`ها (T3) و Kotlin (T4) که بالا گفته شد.

## ۵) قاعده‌ی به‌روزرسانی این فایل

بعد از هر آپدیت:
1. موارد انجام‌شده از بخش ۴ به جدول بخش ۲ منتقل می‌شن (خلاصه و تمیز).
2. بخش ۴ دوباره پر می‌شه تا همیشه **۲۰ پیشنهاد (۱۰ دقت + ۱۰ ظاهر)** داشته باشه؛ پیشنهادهای جدید به اپ و کدش وابسته‌ان.
3. وضعیت اجرا و بدهی‌های فنی به‌روز می‌شن.
4. خروجی هر آپدیت zip با ساختار پوشه از ریشه‌ی پروژه‌ست و دستور PowerShell انزیپ (`Expand-Archive`) همیشه کنارش داده می‌شه. خود این فایل هم داخل zip و در ریشه‌ی پروژه می‌آد.
